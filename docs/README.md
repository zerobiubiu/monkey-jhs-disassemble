## 2. 文档规范

### 2.1 存放位置与命名

- 文档一律存放于 `docs/` 子目录；`docs/` 只放文档及必要的文档资源，不放业务代码。
- 需要顺序管理的文档采用 `NN-描述.md`（如 `243-autopage-click-loader-fix.md`）。
- 持续维护的当前状态文档使用固定名称（`README.md`、`history.md` 等）。
- 每个独立文档分类目录应包含 `README.md`，至少记录文档清单、文档类型、当前状态、推荐阅读顺序、相关代码/配置链接、已废弃与替代关系。

### 2.2 文档类型

| 类型 | 用途 |
|------|------|
| 📋 接口契约 | API、协议、请求响应、错误码和联调约定 |
| 🔧 开发指导 | 待执行/已执行的技术修改方案和验证步骤 |
| 📄 参考说明 | 调试记录、设计说明、现状分析和备忘信息 |
| 🚀 部署运维 | 部署、环境、配置、监控和故障处理 |
| 🧭 架构决策 | 重要技术选型、取舍、影响与替代方案 |
| 🧾 变更记录 | 已经执行的迁移、发布或行为变更 |

### 2.3 文档状态

| 状态 | 含义 |
|------|------|
| ✅ 已执行 | 历史定稿，永不可改（migration 原则） |
| 🔧 待执行 | 尚未实施或进行中 |
| 📄 参考 | 仅作参考 |
| ⚠️ 已过期 | 不再适用 |
| 🚫 已废弃 | 已被删除/取代 |

### 2.4 文档元数据

编号文档头部应包含必要元数据块：

```markdown
> **文档类型**：🔧 开发指导
> **文档状态**：🔧 待执行
> **影响范围**：后端认证模块
> **前置文档**：01-api-contract.md
> **替代文档**：无
> **生效版本**：待定
```

### 2.5 文档治理分类

三个类别，不得混淆：

- **当前状态文档**：描述系统当前有效状态，可随系统演进持续更新（README、当前 API 参考、部署手册、配置说明、运维手册）。
- **不可变变更文档**：记录一次已执行的变更、迁移或架构决策。一旦标记 ✅ 已执行，正文原则上不再修改；发现错误或发生后续变化时，新建后继文档并标明替代关系。允许追加但不得重写的内容：实际执行记录、验证结果、关联提交、已知偏差、后续替代文档链接。
- **追加型历史文档**：如 `docs/history.md`、发布记录或审计日志，只允许增量追加，不重写已有历史。

## 3. 文档相关要求（强制）

### 3.1 代码变更必须同步写文档

**每次修改 `src/` 下的源码（功能逻辑、bug 修复、优化、插件增删等）时，必须在回答用户前同步编写 `docs/NN-描述.md`，不等用户提醒。**

- 小变更（几行代码的 bug 修复/优化）可合并到同一份 doc 中，但必须在背景部分说明合并了哪些变更。
- 大变更（新增/删除插件、架构调整）必须独立一份 doc。
- 文档必须包含：背景、方案、实施（修改文件清单）、执行验证记录（tsc + vite build 输出）、后续验证建议。
- 同时更新本 README 的文档索引（§1.1 新增一行）+ 旧编号映射（§1.2，如涉及）+ `changelog/CHANGELOG.md` + `vite.config.ts` version（按 AGENTS.md §6.1.1 规则）。
- **禁止**只改代码不写文档就回复用户。

### 3.2 编号与定期归并

- 新变更文档编号从 **243** 继续递增（`docs/243-描述.md`…），与历史编号连续，便于检索与映射。
- **定期归并**：变更文档积累到约 20 份或一个功能阶段结束时，按时间线将其精简融合进阶段文档体系（新增阶段文档或并入既有阶段文档），并同步更新本 README 的索引与映射表——防止文档数量再次膨胀。

### 3.3 版本号与文档

- 纯文档修改（`docs/` 下的 `.md`）、纯 `AGENTS.md` 修改不递增 `userscript.version`（见 AGENTS.md §6.1.1）。
- 文档变更若同时含 `src/` 逻辑修改，按 AGENTS.md §6.1.1 正常递增。

### 3.4 执行验证记录

涉及代码变更的文档完成后，在文档末尾追加：

```markdown
## N. 执行验证记录

### 执行环境
### 验证命令
### 实际输出
### 前端或调用方验证
### 验证结论
### 已知限制
```

验证通过后，将文档状态从 🔧 待执行改为 ✅ 已执行。

### 3.5 历史记录

在以下场景向 `docs/history.md` 追加记录（只增量追加，不重写已有历史）：

- 外部行为变化、架构或技术栈变化、API/配置/数据库/部署变化
- 重要缺陷修复、安全相关修改、用户明确要求保留的执行记录

历史条目至少包含：需求摘要、执行结果、影响范围、验证情况、关联文档或提交。
